## 📋 Как добавить новую работу в каталог

Каталог хранится в **Cloudflare KV** (ключ `catalog`) и отдаётся сайту через Worker (`GET /api/catalog`).
Записать каталог можно **только** с компьютера или из панели Cloudflare. С сайта — нельзя: публичная запись отключена, это защита от спама.

### Способ 1 — вручную в панели Cloudflare (проще всего)

1. https://dash.cloudflare.com → **Workers & Pages** → **KV**
2. namespace **CATALOG** → ключ **`catalog`**
3. Открыть значение, вставить/поправить JSON, сохранить.

### Способ 2 — командой с компьютера

Файл `worker/seed-catalog.js` **только печатает готовый JSON** — сам он ничего никуда не пишет. Чтобы данные попали в облако, нужно передать этот JSON команде wrangler:

```bash
cd worker

# 1) сохранить текущее значение каталога — это точка отката
npx wrangler kv key get catalog --binding CATALOG_KV --remote > ../tmp/catalog-backup.json

# 2) записать новый каталог
npx wrangler kv key put catalog --binding CATALOG_KV --remote "$(node seed-catalog.js)"

# 3) проверить, что сайт видит новое
curl -s https://tg-proxy.metalkor91.workers.dev/api/catalog | head -c 200
```

Три вещи, без которых команда не сработает:

| Что | Почему |
|---|---|
| `--remote` | без него wrangler пишет в **локальную** копию хранилища, и на сайте ничего не меняется (самая частая ошибка) |
| ключ — **первым аргументом** (`kv key put catalog …`) | старый вид `--key catalog` больше не поддерживается, команда падает с «Missing required option» |
| `--binding CATALOG_KV` | так команда понимает, в какой namespace писать; альтернатива — `--namespace-id fe7b04ba504643ce9f085d1213bd5a09` |

Ещё нужен токен Cloudflare с правом **Workers KV: Edit** — в неинтерактивном режиме wrangler без него отказывается работать:

```bash
export CLOUDFLARE_API_TOKEN="..."    # токен деплоя из .env, в репозиторий не попадает
```

**Откат** (если в каталоге что-то сломалось):

```bash
cd worker
npx wrangler kv key put catalog --binding CATALOG_KV --remote "$(cat ../tmp/catalog-backup.json)"
```

**Безопасная проба без риска для прод-каталога:** те же команды с `--local` вместо `--remote` — данные лягут в локальное хранилище на компьютере, сайт их не увидит.

**Формат данных CatalogItem:**

| Поле | Что писать | Пример |
|------|-----------|--------|
| `id` | Уникальный номер | `11` |
| `name` | Короткое имя (до 200 знаков) | Чехол для ключа BMW |
| `description` | Что это и для чего (до 1000 знаков) | Защитный чехол, PLA, 2 цвета |
| `image` | Путь к фото (см. ниже) | `images/bmw-cover.jpg` |
| `category` | Категория (см. ниже) | `techno` |
| `material` | Материал печати (до 100 знаков) | PETG / ABS |
| `price_s` | Цена маленький | `320 ₽` |
| `price_m` | Цена средний | `580 ₽` |
| `price_l` | Цена большой (оставь пустым если нет) | `850 ₽` |

**Категории:**

| Значение | Что это | Примеры |
|----------|---------|---------|
| `techno` | Технические детали, запчасти, крепления | Шестерни, кронштейны, чехлы, заглушки |
| `decor` | Игрушки, декор, фигурки | Ночники, статуэтки, сувениры |

Если в записи что-то не так (нет имени, чужая категория, битый путь к фото) — сайт просто не покажет эту работу, остальные останутся. Совсем битый каталог сайт тоже переживёт: покажет «Попробовать снова», а не пустой экран.

## 📸 Как добавить фото

Только один путь: **положить файл в папку `images/` и закоммитить его**, а в записи каталога указать **относительный** путь — например `images/moyo-foto.jpg`.

Внешние ссылки (imgur и любые другие сайты) **не работают**: Worker пропускает только относительные пути, начинающиеся с `images/`. Это защита от подмены картинки на чужой сайт.

Требования к имени файла (иначе запись отбросят):

- латинские буквы, цифры, знак `-`, `_`, точка;
- пробелов и кириллицы быть не должно: `images/figure hero.jpg` ❌ → `images/figure-hero.jpg` ✅;
- расширение из списка: `jpg`, `jpeg`, `png`, `gif`, `webp`, `svg`.

Порядок: положить фото в `images/` → закоммитить и запушить в `main` (GitHub Pages обновляется сам) → вписать путь в каталог → обновить KV (см. раздел выше) → проверить `GET /api/catalog`.

## 🐱 Фигурка в шапке главной страницы

Справа в блоке услуг стоит вырезанная фигурка (фон убран). Слева — анимированный принтер, так что композиция симметричная.

Инструменты: `tools/gen_variant.py`, `tools/ai_repaint.py`, `tools/figure_from_ai.py`, `tools/figure_check.py`. Нужны ключи Cloudflare в `.env` — в репозиторий они не попадают.

```bash
# проверить готовый ассет (альфа, аспект, две ноги)
python tools/figure_check.py --in images/figure-hero.webp
```

Когда раскуришь фигурку по-настоящему и сфотографируешь — замена делается одной командой:

```bash
python tools/figure_cutout.py --in "новое-фото.jpg" --out images/figure-hero.webp
python tools/figure_check.py --in images/figure-hero.webp
```

**Важно:** после замены картинки поднимай номер версии в `index.html` (`images/figure-hero.webp?v=6`), а если менялся CSS — `styles/main.css?v=16` на всех четырёх страницах. GitHub Pages кэширует статику 10 минут: без смены номера увидишь старое.

## 📝 Что в форме заявки

| Поле | Зачем |
|------|-------|
| Ваше имя, телефон или Telegram | чтобы связаться с клиентом |
| Краткое описание проекта | что за деталь и для чего |
| 📎 скрепка в поле описания | клиент прикладывает фото, чертёж или 3D-модель прямо с компьютера или телефона |
| Материал | PLA (универсальный), PETG (прочный), ABS (термостойкий, ударопрочный) или «Другой / не знаю» |
| Цвет материала | клиент пишет словами: чёрный, белый, красный |
| Количество копий | сколько штук печатать |

Под формой — таблица «Какой материал выбрать?»: термостойкость и применение каждого пластика.

Пустая форма больше не отправляется: сайт подсвечивает поля, которые надо заполнить, и переводит курсор к первому из них.

##  Как посмотреть заявки

Заявки с сайта приходят **в Telegram** — бот отправит сообщение с данными клиента.
Если клиент что-то приложил к заявке, файлы приходят **следом отдельными сообщениями-документами** — их можно скачать и распечатать сразу.
Сейчас лимит вложений: **до 5 файлов, каждый до 15 МБ** (и не больше 40 МБ на всю заявку). Если файл больше — клиенту нужно прислать ссылку в описании.

Что можно приложить: `.stl`, `.obj`, `.3mf`, `.step`, `.stp`, `.igs`, `.iges`, `.dwg`, `.f3d`, `.zip`, `.rar`, `.pdf` и картинки (`.jpg`, `.jpeg`, `.png`, `.webp`, `.heic`, `.gif`).

Если что-то не дошло — напиши, разберёмся.

## 💬 Как добавить отзывы

Отзывы — **курированные**. Добавляются вручную в файл `scripts/reviews.js`.

1. Открой файл **`scripts/reviews.js`**
2. Найди массив `REVIEWS_DATA = [`
3. Вставь отзыв по образцу (образец есть в комментариях файла):

```js
  {
    "name": "Алексей",
    "text": "Заказывал кронштейн для регистратора. Сделали за два дня, встал как родной.",
    "stars": 5,
    "date": "Август 2026"
  },
```

4. Сохрани файл (Ctrl+S)

Пока отзывов нет — секция целиком скрыта на сайте. Добавишь первый — она появится сама.

Пользовательская форма «Оставить отзыв» отправляет отзыв **в Telegram** (владельцу), но не публикует на сайте. Отзывов с одного адреса — не больше 3 в час, остальное сайт вежливо отклонит.

## 🚀 Как работает сайт

- Хостинг: **GitHub Pages** (бесплатно)
- Каталог товаров: хранится в **Cloudflare KV**, загружается через Worker API (только чтение)
- Отзывы: **`scripts/reviews.js`** (курированные) + отправка в Telegram
- Клик по фото в каталоге → открывается большим (лайтбокс); с клавиатуры — Tab + Enter
- Уведомления: **Telegram-бот** (присылает заявки и приложенные файлы тебе)
- У публичных адресов Worker есть защита от спама: лимит заявок с одного адреса (5 в час) и отзывов (3 в час), проверка origin, а при подключённых ключах Turnstile — ещё и капча

## ⚙️ Технические детали

```
3dprint-site/
├── index.html          ← главная страница
├── works.html          ← каталог работ (клик по фото = лайтбокс)
├── order.html          ← страница заявки + таблица материалов
├── reviews.html        ← книга клиентов (отзывы)
├── images/             ← фотографии работ + фигурка для шапки
├── styles/main.css     ← общие стили всех страниц
├── scripts/
│   ├── catalog.js      ← загрузка каталога из Worker API + отрисовка
│   ├── order.js        ← форма заявки: проверка полей, вложения, повтор при сбое
│   ├── review-form.js  ← форма отзыва: звёзды, «спасибо» только после ответа сервера
│   ├── reviews.js      ← курированные отзывы клиентов
│   └── common.js       ← мелкие утилиты (меню, XSS protection)
├── tools/              ← Python-инструменты для подготовки ассетов
├── worker/             ← Cloudflare Worker: заявки и файлы в Telegram, каталог из KV
│   ├── src/            ← код Worker'а (роутер, валидаторы, идемпотентность)
│   ├── tests/          ← тесты без деплоя: `cd worker && node tests/run-tests.js`
│   └── seed-catalog.js ← заготовка каталога (печатает JSON)
├── sketches/           ← черновики дизайна (на сайт не влияют)
├── README.md           ← этот файл
├── DEPLOYMENT.md       ← как обновлять Worker и сайт, откат
└── .env.example        ← шаблон переменных (реальные секреты — в .env, он не в git)
```

**Важно для правок:** ассеты подключаются с версией (`styles/main.css?v=16`, `scripts/*.js?v=…`). GitHub Pages кэширует статику 10 минут, поэтому после правки CSS или скриптов номер версии нужно поднять — иначе посетители увидят старый файл.

**Деплой сайта:** при каждом push в ветку `main` сайт обновляется автоматически на GitHub Pages.

**Деплой Worker'а:** вручную, отдельной командой (порядок и откат — в `DEPLOYMENT.md`):

```bash
cd worker
npx wrangler deploy --dry-run      # только проверка сборки, ничего не публикует
npx wrangler deploy                # публикация
```

##  Частые вопросы

**Товар не появляется в каталоге**
→ Проверь, что данные записаны в Cloudflare KV (ключ `catalog`) и что команда шла с `--remote` (без него запись уходит в локальную копию)
→ Убедись, что фото лежит в `images/` и имя файла без пробелов и кириллицы
→ Открой `https://tg-proxy.metalkor91.workers.dev/api/catalog` — там должно быть видно новую работу

**Хочу изменить текст на сайте**
→ Напиши мне, я поправлю HTML.

**Сайт не открывается**
→ Проверь ссылку: `https://rudrymor.github.io/3dprint-site/`
